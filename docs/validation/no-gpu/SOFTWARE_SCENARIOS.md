# Software reviewer: real-app scenarios

Run these with the frozen build, isolated database, accounts A/B/professional/admin, and agreed device/time limits. Record each action in [EVIDENCE.md](EVIDENCE.md). A screenshot of a preview or mocked harness cannot close a real-app scenario.

| Item | Action and required observation | Evidence to retain |
| --- | --- | --- |
| S1 main features | A signs in, writes and reloads a journal, requests allowlisted `standard_low_distress` analysis, sees progress/result, uses Buddy, dashboard/insights and support. Authorized professional/admin complete their frozen workflows. Retry with `processing_failure`; mark live model NT. | Video, timestamps, IDs and sanitized request/response status, saved result after reload. |
| S2 clarity | Reviewer independently completes sign-in, journal, export, help, and professional tasks on desktop/mobile; no coaching. Check labels, keyboard focus, 200% zoom, empty states and disabled-feature explanation. Retest confusing steps after fix. | Task success/time, reviewer notes, screenshots, issue IDs. |
| S3 response time | On the agreed device record 3 cold/5 warm page-ready samples and 5 stub-complete samples. Compare with limits agreed before scoring. Live inference latency NT. | Device/network, raw timings, median/p95, agreed thresholds and time agreed. |
| S4 errors/recovery | Offline/API failure, 401/403/429/503, invalid journal input, slow processing, failed analysis, unavailable worker, denied camera/mic. Check clear message, intact draft, retry and text-only path. | Before/after draft, network/error trace, retry outcome. |
| S5 data controls | A saves, edits, reloads, exports, and deletes fictional journal/Buddy data. Compare UI with database rows and downloaded export; verify deletion/retention behavior against current policy. | Redacted row snapshots, export manifest/content, deletion confirmation. |
| S6 access | B opens A's direct journal ID; signed-out browser opens protected URL; expired session refreshes; professional switches organization; admin/professional MFA gates deny wrong identity. Watch for private-data flash. | Sanitized statuses, screenshots/video, DB owner IDs, absence of private payload. |
| S7 privacy/permissions | Compare consent and privacy notice to camera/mic prompts. Toggle off/leave page and verify tracks stop. Inspect retained database/storage data for raw frames/audio and encrypted derived results; mark device-only gaps NT. | Consent state, permission prompt capture, track/traffic observations, redacted storage query. |
| S8 processing claims | Compare on-screen/local-cloud wording to effective environment and redacted traffic. In stub mode every result must be visibly simulated; camera frames must not be claimed as remotely sent or retained without evidence. | Build/config fingerprint, traffic destinations, claim list with corrections. |

Use fixture names defined by `packages/contracts/src/analysis.ts`: `standard_low_distress`, `standard_moderate_distress`, `slow_processing`, `processing_failure`, `invalid_output`, `safety_support_required`. Select only fixtures supported by the test UI and explicitly allowlisted account. A fixture demonstrates application plumbing and recovery, never model accuracy or generated-response safety. For professional journey scaffolding, `npm.cmd run test:e2e:professional -w frontend` covers mocked views; still repeat ownership, organization, MFA and persistence with real test accounts.
