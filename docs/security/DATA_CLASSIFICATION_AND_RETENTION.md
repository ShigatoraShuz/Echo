# Data classification and retention

Review: 2026-09-21. Owner roles below require named human assignment. Retention durations are proposed engineering defaults, not an approved legal policy. No existing user data has been removed. Production is blocked until approval and complete lifecycle tests.

| Category / module | Fields and purpose | Classification | Proposed retention / deletion | Backup / provider behavior | Current enforcement |
| --- | --- | --- | --- | --- | --- |
| User / profiles | Display name, timezone, eligibility facts, preferences; account operation | Confidential; identity descriptors sensitive | Account lifetime; delete after approved 30-day cancellation window | Expire in encrypted backups within approved 35-day maximum | Owner filters; scoped settings RLS; full deletion worker pending |
| User / consent | Type, version, acceptance, timestamp, source; prove informed processing | Confidential | Account lifetime plus legally approved evidence period; pseudonymize after deletion | Same backup window; no provider transmission | Versioned rows exist; append-only history/withdrawal audit needs review |
| User / contacts | Name, email, phone, relationship; user-selected safety support | Confidential | Until removed or account deletion | No AI transmission; backup expiry | Owner CRUD; verified flag protected |
| Journals / entries and drafts | Title/body, mood/tags; private reflection | Restricted | Until user deletion/account deletion; abandoned drafts proposed 90 days | No plaintext backups; backup window applies | Title/body AES-GCM; metadata/read-model encryption inventory incomplete |
| Journal / images | Personal attachments | Restricted | Entry/account deletion; abandoned-upload cleanup | Encrypted restricted backups; no public URLs | Private bucket, cleanup service; deployed policy tests pending |
| Buddy / messages | User and assistant text; support conversation | Restricted | Until conversation/account deletion; proposed inactivity review at 1 year | Current Buddy replies local; no external provider | New writes encrypted; legacy backfill required |
| Verification / records and documents | Identity evidence, reviewer decision; access assurance | Restricted | Delete documents proposed 30 days after final decision; minimal decision evidence per approved policy | Scanner must not train/retain; backup expiry | Encrypted designated fields, private quarantine, clean-only reviewer access; deletion job pending |
| Analysis / requests and results | Job, risk/insight output; consented analysis | Restricted | Raw payload minimal lifetime; derived results entry/account lifetime; operational job metadata proposed 30 days | Provider retention/training disabled by contract; deletion receipt required | Existing analysis retention script; new detailed results encrypted; historical results, safety index and other readmodels/provider deletion incomplete |
| Wellness / grounding / insights | Check-in answers, activity and derived trends | Restricted for mental-health details | Account lifetime or user deletion; no advertising reuse | Same backup window | New PHQ-8 answer/score/severity payload encrypted; historical backfill and other Restricted fields remain pending |
| Notifications | Type, opaque journal reference, generic text | Confidential | Proposed 90 days or account deletion | Never include journal/Buddy body | Scoped JWT client; owner RLS; read_at-only update |
| Audit / security events | Actor hash or UUID, event code, timestamp, outcome | Confidential | Proposed 180 days; approved minimal evidence exception for incidents | Restricted append-only archive; incident legal hold must be recorded | Runtime INSERT/SELECT only; durable external archive pending |
| Exports | Complete user-owned data package | Restricted | Proposed 24-hour expiry, one-time authenticated download | No analytics or email attachment; encrypted object only | Encrypted account archive, recent-authenticated single-use download, 24-hour expiry and cleanup implemented; large-account/live provider delivery review pending |
| Signup drafts | Temporary account/policy preparation | Confidential | Existing expiry/cleanup contract; verify deployed job | No production fixtures | Existing registration cleanup; deployed evidence pending |
| Public directory | Approved Philippine support contact listings | Public | Editorial review at least quarterly | No user data | Public content routes |

Field inventory is reproducible from DATABASE_CATALOG.json columns. Each new column requires a classification and purpose review. The table above does not claim that every Restricted field is already encrypted.

Deletion must use a retryable state machine: freeze new processing; revoke sessions; cancel analysis; enumerate private objects by database-owned paths; delete objects and record receipts; delete relational/derived rows in a transaction; remove Auth identity last; retain a minimal non-content completion tombstone; verify no orphan rows/objects. A failed storage/provider operation must keep the request retryable, never falsely completed. Restore procedures must reapply deletion tombstones before making restored data accessible. This complete worker is not implemented yet.

Deletion request admission and cancellation now use service-only transactional RPCs with per-user locking and mandatory audit writes. Tests cover idempotent request retries, timezone-independent schedules, wrong-owner cancellation denial, processing-state protection and rollback on audit failure. This improves request integrity; it does not erase an account or implement the missing deletion worker.
